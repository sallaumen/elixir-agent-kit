# Live evaluation: Codex CLI, 2026-11-07

Consumer: agent-board `main` `ee83962` (Elixir Agent Kit v0.6.0, `skills: :all`, adapters
codex, claude, generic). Client: Codex CLI 0.162.1, `codex exec --json --ephemeral`,
`--sandbox workspace-write`, `approval_policy=never`, web search disabled, the model and
endpoint from the operator's `~/.codex/config.toml` (a cloud model served through the
local Ollama proxy; per-run cost is not reported by that endpoint, so token counts stand
in for it). The operator's global `~/.codex/AGENTS.md` (the `mcptoon skills resolve`
rule and the playbook skills) was present, as in the Claude sessions. Same prompts as the
Claude evaluation (the routing case text plus one sentence of project context and the
closing request to list the files read and the workflow chosen), three disposable
worktrees reset between runs. The JSONL event streams are the evidence.

Columns: "Pointer", "START", "SKILL", "Contract" and "First source" are the index of the
shell command that first read `.agents/skills/elixir-agent-kit/SKILL.md`, `START.md`, the
workflow's `SKILL.md`, the maintainer contract and a `lib/` file (Codex reads through
`cat`/`sed`, so this counts commands, not model turns). "Global" counts reads of skills
under the operator's home directory. Tokens are input/output for the run.

## Reading

- Discovery works on Codex the way the compatibility table says: every run read
  `.agents/skills/elixir-agent-kit/SKILL.md` or `START.md` within its first four
  commands, the workflow's `SKILL.md` within its first eleven, and in 15 of 15 runs
  before any `lib/` file. The operator's `mcptoon skills resolve` rule returned the
  pointer skill by name in the runs that called it, so the project skill is visible to
  that catalog now.
- Routing is 15/15 on the expected workflow; every final report ends with a "Workflow
  escolhido" line naming the workflow and the kit version, in the request's language.
- With the suite runnable, all six backend runs finished with a tested fix. The E32 runs
  found the same stale-overlay mechanism the Claude sessions found and chose a different
  repair (match tickets by repository and issue URL, not issue number alone); the E44
  runs found the empty-answer-as-success and the cross-provider retry after 401/429,
  made `AI.call` single-attempt and recorded the attempt before the network, which is
  the provider-calls rule set. Every run wrote tests next to the fix and ran the whole
  suite at least once (509 to 510 passed).
- Codex sessions are shorter than Claude's (51 to 92 commands, 6 to 15 minutes) and none
  delegated.
- The sandbox, not the kit, decided the first batch: with no network no run could prove
  its change, and three E05 runs tried to start a dev server and a headless browser on
  the operator's machine before giving up, which the harness should forbid explicitly.

## Limits

- One client, one configured model through a local proxy, 15 runs, on the operator's
  machine with the operator's global Codex instructions present. Token counts are not
  costs. The DeepSeek executor was not evaluated.
- "Routed" is which `SKILL.md` was read; the first batch could not run tests, so its
  "finished" state is source inspection only.
