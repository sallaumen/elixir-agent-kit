# Domain workflows: eight paired reviews, November 13, 2026

Six baseline workflows gave a correct review decision once the task supplied the relevant evidence. Two required a wording change: the baseline treated a bundle as if the parent's eligibility could suffice, and treated recovery of an editable historical asset as moving a pointer. On both, the amended guide changed the decision on the failing case and retained the correct behavior on a separate real control.

## Protocol

The evaluator selected eight existing workflows in an authorized Elixir application: five snapshots immediately before a historical fix and three existing operational flows. The initial per-case criteria were written before invoking either reviewer. In particular, a duplicate-delivery test had to observe the transport, not just the audit table; a package test had to change one included component while the parent remained eligible; and editable recovery had to preserve independent artifact ownership. The evaluator checked the answers against source, fixes and tests that were withheld from the reviewers. The evaluator knew the arm labels; this was not blind scoring.

Each pair used separate ephemeral Codex CLI sessions (0.162.1, `gpt-6.1-sol`, medium), an empty read-only working directory per arm, identical source excerpts and question, and the same answer limit. The sessions were asked for a review using only the supplied material. A received no Kit instructions; B received the baseline workflow and shared contract from `5f59112`. For changes, fresh sessions compared the old and candidate guides with the same contract, first on the original case and then on a separate control. No expected answers, later fixes, private application prompts or previous responses were provided as instructions.

**32 model sessions:** 16 first-pass, six with missing evidence restored to both arms, two with an explicitly requested recurrence control, four old/candidate comparisons, and four old/candidate transfer controls. The logs identify distinct sessions and show no model-issued tools, shell commands or additional reads. User configuration and rules were ignored. Host-skill discovery, skill search and plugins were explicitly disabled for the ten candidate/control and recurrence sessions; the initial and expanded-evidence sessions did not set those additional switches. Some earlier logs show the client attempting a background plugin catalog refresh, not a model tool call. This tests using a supplied guide, not autonomous discovery or editing. The raw private material is not part of this repository.

## What the candidate changes bought

- **Commercial eligibility:** trace the actual contents of a purchase before deciding which offers must pass. The separate control used a real cart covering only the participant's owed days. Both old and new guides correctly excluded an unowed sibling, preserved the parent gate, and identified the different checks for newly minted and reused carts. No cart checkout was executed. Candidate file SHA-256: `3e58a79797c7192e255ab5a4b68b01bd25052e65a850684aa2fa1a5709795f71`.
- **Revision lineage:** distinguish moving a publication pointer from copying an old asset for further editing. The separate control used explicit rollback of a published image: both guides correctly rejected creating a new candidate and required an identical second click to leave the audit unchanged. Two existing rollback tests passed. Candidate file SHA-256: `88ee9430c14b55ffcd2913c3d1e3047a080b6fd57b99b348cd73f39e7adc4022`.

The independent execution comprised **13 passing application tests** (11 existing cases and two focused evaluator checks), plus the isolated selector and historical gate probes described above. The source worktree was not changed. The commercial case validates a composite sale with real seller/route rules, not a supplier shipment to a particular country. No live supplier catalog, provider invoice, bank response, production alert or external concurrency measurement was used. Correct ties justify retaining the guides on these cases; they do not establish superiority over an unguided reviewer, or validate cases beyond those tested.
