One run so far, on `forrozin_page` at kit v0.10.0. Each entry: what helped,
where the text misled or missed, where size cost, and the concrete change
proposed (or "none").

## readable-code (E64-r1, medium) — extract a nested `case` into a named function

- **What helped.** The workflow's step 4 ("reshape control flow by meaning:
  branch with function heads and pattern matching instead of nested `case`")
  matched the project's own house rule word-for-word, so the route was obvious
  and the work was a straight extract. The new `## Size` "Medium" line ("run the
  workflow as written") plus the contract's medium plan rule (first-step
  artifact in the reply, no plan file) kept the task from being over-planned.
- **Where text misled or missed.** Nothing. The only friction was environmental
  (a fresh worktree had no `assets/node_modules`, so `mix precommit` failed 4
  pre-existing JS tests on `d3-geo` before `npm install --prefix assets`); this
  is not a workflow-text issue.
- **Where size cost.** None. Medium was the right call; a plan file would have
  been noise for a two-function extract.
- **Concrete change proposed.** None.

## readable-code (E64-r2, medium) — extract a nested `|> case` into a named function

- **What helped.** Same as E64-r1: step 4 matched the house rule exactly; the
  extract was mechanical.
- **Where text misled or missed.** A process error, not workflow text: I first
  targeted `refunds.ex` from a stale read of the main checkout, but `origin/main`

  fresh `origin/main` worktree, which the workflow's "Start at" input already

- **Concrete change proposed.** None.

## "No real need" for the remaining code/backend workflows

The four field projects are heavily self-governed: each carries machine-enforced
coding-standard guards that already prevent the defect class the corresponding
kit workflow guides, so a live round found no pending instance for these
workflows. This is a finding, not a claim that the workflows are unnecessary —
only that these projects' own guards preempt the need.

- data-contracts: `context_boundary_test` + `context_layers_test` (forrozin_page,
  o_colmex) enforce single field ownership and layer separation; no multi-owner
  field was found.
- migration-compatibility: o_colmex `pragmatic-automatic-migrations` policy and
  forrozin_page "backfills never in migrations" + `migration_index_test` already
  govern expand/contract; no pending persisted-shape change.
- security-boundaries: forrozin_page `Authorization.Policy` at the edge and
  o_colmex `current_scope` + scoped queries are machine-enforced; beatgrid and
  pokex are single-user local apps. No pending tenant/scope leak.
- provider-calls: beatgrid's Soundcharts/AudD budget guards (`api_calls` ledger,
  sandbox creds) and o_colmex's registered brain calls with cost rows already
  implement the budget-before-network, one-audit-row discipline.
- data-pipelines: beatgrid's import/scan flow (dedup, idempotency, per-track
  queues) is implemented and recently hardened (#97-#100); no pending flow defect.
- abstraction-layers: `context_layers_test` enforces calculations-vs-actions; no
  pending function mixing a decision with effects.
- module-design: `naming_contract_test` + `english_code_test` enforce names; no
  pending misleading public API.
- code-consolidation: no dead or competing path was found.
- house-patterns: `module_layout_test`, `list_idioms_test`, `pipe_layout_test`,
  `with_and_case_test` already enforce the house patterns; no drift.
- functional-refactoring: `context_layers_test` keeps hidden inputs out of
  calculations; no module interleaving hidden inputs, decisions and effects.
- test-strategy: TDD plus a `coveralls.json` floor and `test_shape_test` are in
  force; no uncovered-risk gap.
- code-review: no open PR was pending during the round, so there was no bounded
  diff to review.
- debugging: no wrong-result or intermittent failure was reported.
- performance: no measured latency/freeze/memory issue was reported.
- async-state: no stale-result or out-of-order race was reported.
- process-lifecycle: beatgrid's 26 Oban workers all follow the stated error
  semantics (`{:cancel, _}`/`{:error, _}`, `enqueue` wrappers, uniqueness); no
  blocking/leak/restart defect.

architecture-review has a real, documented need (facades over the 400-line
