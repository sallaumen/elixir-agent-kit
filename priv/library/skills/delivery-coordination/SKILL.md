# Delivery Coordination

Default mode: **coordinate**. Read the [shared contract](../../CONTRACT.md) before applying this workflow. The user's explicit scope overrides the default mode.

## When to use

Use when consolidating a product or dividing an authorized change into reviewable deliveries.

## Useful inputs

The requested outcome, affected flow or diff, project instructions, relevant evidence and acceptance criteria. Discover available context before asking for missing information.

## Workflow

1. Map the actual product areas, active work and unfinished flows before making a delivery plan. Distinguish features to finish, simplify, retain or retire using evidence of usage and ownership.

2. Split the selected outcome into independently reviewable changes with explicit inputs, boundaries, dependencies and acceptance criteria. Name one owner for shared contracts and files. Integrate dependent work sequentially.

3. Delegate only when the user and environment permit it and the work benefits from parallel execution. Give each worker a bounded assignment, wait for results, and resolve shared-file conflicts before integration. Without delegation tools, execute sequentially.

4. Track completed, blocked and deferred work separately. A worker report is evidence to inspect, not proof of an integrated result.

## Completion

A delivery map, validated integrated changes within the mandate, and a handoff identifying remaining dependencies. Coordination does not grant permission to publish or deploy.

Use the [Elixir context](../../ELIXIR.md) only for technology present in the project. Record a useful [handoff](../../HANDOFF.md) when another person or agent will continue the work.
